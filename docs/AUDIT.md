# Аудит исходного кода SMP 1.x

Документ описывает дефекты, найденные в исходной версии проекта (коммит
`a01037d`, папки `src/`, `include/`, `Makefile`, `shell.nix`) и то, как каждый
из них устранён в версии 2.0. Номера строк относятся к исходной версии — она
сохранена в истории git.

Уровни: **critical** — падение, порча памяти или удалённое выполнение кода;
**major** — неправильная работа, гонки, утечки, зависания; **minor** —
неудобства, мёртвый код, устаревшие практики.

## 1. Порча памяти и неопределённое поведение

| № | Место | Проблема | Исправление |
| --- | --- | --- | --- |
| 1.1 | `src/audio.c:208-212`, `:285-292` | `playlist.tracks[playlist.current]` читается **до** проверки `current < count`. После последнего трека `current == count` → чтение за границей массива, падение или мусор в `position`. | Движок (`src/player.c`) хранит собственный индекс и обращается к треку только через `smp_playlist_at()`, который возвращает `NULL` для недопустимого индекса. |
| 1.2 | `src/ui.c:176-194`, `:253-261` | VLA `char title_display[RIGHT_WIDTH - 2]` и `track_display[RIGHT_WIDTH - 6]`, затем запись по индексам `RIGHT_WIDTH - 13`. При узком терминале (или после смены формулы ширины) индекс отрицательный → запись в стек до буфера. | Кадровый буфер (`src/frame.c`) фиксированного размера; текст рисуется в ячейки с проверкой границ, обрезка выполняется через `smp_utf8_ellipsize()`. VLA не используются (`-Wvla` в сборке). |
| 1.3 | `src/ui.c:334`, `:344` | `display_left_panel()` вызывает `check_tiv_available()` при каждой перерисовке, а тот — `system("which tiv")`. Это порождение процесса ~10 раз в секунду. | Внешняя утилита `tiv` не используется вовсе; обложка декодируется `stb_image` и кэшируется один раз на альбом. |
| 1.4 | `src/file_utils.c:83-88` | `snprintf(command, "tiv \"%s\" …", image_path)` + `popen()`. Файл с именем `"; rm -rf ~ #.jpg` даёт выполнение произвольной команды. | Весь код работы с процессами удалён. Формирование изображения выполняется внутри процесса. |
| 1.5 | `src/ui.c:466-506` | После `ESC` два блокирующих `read()`. Нажатие одиночного `Esc` заставляет интерфейс ждать следующей клавиши — «зависание». | Ввод на POSIX идёт через `poll()` и буфер с разбором неполных escape-последовательностей (`src/plat/term_posix.c`); на Windows — через `ReadConsoleInputW`. Одиночный `Esc` обрабатывается по таймауту. |
| 1.6 | `src/main.c:94-97` | `pthread_mutex_init()` вызывается для мьютексов, уже инициализированных `PTHREAD_MUTEX_INITIALIZER`. Повторная инициализация — UB. | Абстракция `smp_mutex_create()` создаёт примитивы ровно один раз (`src/plat/thread_*.c`). |
| 1.7 | `src/player.h:6` | `#define _POSIX_C_SOURCE` **внутри** заголовка, который в `main.c` подключается после `<pthread.h>` — макрос объявлен слишком поздно и не действует. | Feature-test macros задаются на уровне сборки (`target_compile_definitions`) и в начале каждого POSIX-файла до системных заголовков. |
| 1.8 | `src/playlist.c:46-52` | `snprintf(fullpath, 1024, …)` молча обрезает длинный путь; `Track.filename[256]` обрезает его ещё сильнее → попытка открыть несуществующий файл. | Пути не ограничены фиксированным буфером: `smp_path_join()` выделяет память под точную длину, `SmpTrack.path` — `char *`. |
| 1.9 | `src/ui.c:587-589` | `set_cursor_position()` принимает произвольные координаты; отрицательные значения превращаются в мусорные escape-последовательности. | Все операции кадрового буфера проверяют координаты; отрицательный `x` не пишет ничего. |

## 2. Потоки и состояние

| № | Место | Проблема | Исправление |
| --- | --- | --- | --- |
| 2.1 | `src/playlist.c:254-275`, `src/audio.c:315-330` | `start_playback()` создаёт новый поток, не дожидаясь завершения предыдущего. Два потока одновременно пишут в один `pcm_handle` → рваный звук, гонки на `playlist.playing`. | Один постоянный рабочий поток; смена трека выполняется через счётчик поколений (`generation`) под мьютексом. Второго потока не бывает в принципе. |
| 2.2 | `src/main.c:158-162` | `pthread_join()` вызывается только если поток ещё работает. Поток, завершившийся сам, не присоединяется → утечка стека и дескрипторов на каждый переход трека. | Поток создаётся один раз в `smp_player_create()` и присоединяется в `smp_player_destroy()`. |
| 2.3 | `src/main.c:56-78`, `src/audio.c:182-217` | `playback_thread_running`, `playlist.playing`, `playlist.current`, `playlist.position` — обычные `int`, которые пишутся из UI-потока и читаются из аудиопотока без синхронизации. Формально UB (C11 §5.1.2.4), практически — потерянные обновления и зависшее состояние. | Всё разделяемое состояние под `SmpMutex`; UI получает согласованный снимок `SmpPlayerSnapshot` через `smp_player_snapshot()`. |
| 2.4 | `src/main.c:60` | Позиция считается по стенным часам (`current_time - playback_start_time`), а `src/audio.c` в это же время пишет позицию по декодированным кадрам. Два источника истины дают скачки таймера. | Позиция — только из декодера (`smp_media_position()`), время не участвует. |
| 2.5 | `src/playlist.c:243-252` | Пауза не корректирует `playback_start_time`, поэтому после снятия с паузы позиция «прыгает» вперёд. | Состояние `PAUSED` останавливает цикл декодирования; позиция сохраняется и продолжается с того же места. |
| 2.6 | `src/main.c:37-84` | `volatile sig_atomic_t` используется как полноценный флаг, а обработчик сигнала вызывает `draw_interface()` — не async-signal-safe вызов (мьютексы, `malloc`, `printf` из обработчика). | `SIGWINCH` только пишет байт в self-pipe; перерисовка выполняется в главном цикле. |
| 2.7 | `src/main.c:147-156` | Главный цикл крутится с `msleep(50)` и перерисовывает экран независимо от изменений — 20 пробуждений в секунду впустую. | Цикл ждёт события (`smp_term_poll`) с таймаутом кадра; перерисовка ≤ 12,5 раза в секунду, кадр отправляется одним `write`. |

## 3. Аудио

| № | Место | Проблема | Исправление |

| 3.2 | `src/audio.c:46-55` | Частота дискретизации жёстко 44100 Гц; файл 48 кГц играет с неверной скоростью и тоном. | Устройство всегда работает на 48 кГц, вход ресемплируется линейной интерполяцией с сохранением состояния между блоками. |

## 6. Что появилось в 2.0

- `smp --help`, `--version`, `--list-devices`, `--audio <backend>`, `--render-once`
- перемотка на 5 секунд, регулировка громкости, перезагрузка библиотеки, экран помощи
- поддержка Windows (WASAPI) при сохранении Linux-таргета
- корректное отображение кириллицы, CJK и эмодзи
- единый стиль кода, `.clang-format`, `.clang-tidy`, `-Werror` в CI
- документация: `docs/ARCHITECTURE.md`, этот аудит, README с таблицей клавиш

## 7. Известные ограничения

- Поддерживаются только WAV и MP3; Ogg/FLAC/Opus не читаются.
- Ресемплинг — линейная интерполяция: для плеера этого достаточно, но это не
  аудиофильское качество.
- Длительность MP3 оценивается по заголовку Xing/Info/VBRI или по битрейту
  CBR; для экзотических VBR-файлов без Xing значение может быть неточным.
- Обложки читаются из файлов (PNG/JPEG/BMP/GIF); встроенные в теги
  APIC-картинки пока не поддерживаются.
